# 2026-11-01

## CI 改造：release-build.yml 支持手动选架构

**背景**：原 workflow 只有 `on.push.tags`，没有 `workflow_dispatch`，所以 Actions 页面没有 "Run workflow" 按钮；本地也从未打过 tag，因此一次都没跑过。

**改动**（`.github/workflows/release-build.yml` 全量重写）：

- 增加 `workflow_dispatch`，三个输入：`arch`（自由文本，空=精选/all=全部/单值）、`tag`（choice）、`release_tag`（可选，留空则只产生 Actions artifact，不创建 Release）
- 新增 `prepare` job，用内嵌 Python 生成动态 matrix：`ALL_ARCHES`(32) / `DEFAULT_ARCHES`(9) / `ARCH_ALIAS` / `SKIP` 四份数据集中在 prepare
- 把原来的 `EFFECTIVE_ARCH` 映射和 `SKIP_BUILD` 判断从 build job 的 shell 分支前置到 prepare，无效组合不再启动 runner
- push tag 触发改为跑精选 9 架构 × 2 版本 = 18 job（原来 32×2=64）
- build job name 改为 `${{ matrix.pkg_arch }}`，tar 包名同步

**保留的坑**：`actions/checkout@v6`、`sbwml/openwrt-gh-action-sdk@go1.27` 未动；打包步骤保留 `continue-on-error`。

**验证**：本地用 PyYAML 解析确认结构合法，并用 8 组环境变量组合跑通内嵌脚本（push/精选/单架构/all+all/无效组合/别名映射/错误架构名/指定 release_tag）。all+all 输出 63 job（64 - mips_4kec@25.12）。

**分支与提交**：新建本地分支 `dev`（从 `v5` 的 `dbdd91a` 拉出），拆成两个 commit 并推送到 `origin/dev`：

- `661a2af` ci: 支持手动选择架构编译，push tag 改为精选架构矩阵（含 PROJECT_wiki.md、.workbuddy/memory）
- `aeab7eb` luci-app-mosdns: 新增自定义上游分流功能（route.js / route.uc / init.d / rpcd / menu / acl / po）

**关键坑（未解决）**：GitHub 只在**默认分支**上注册 `workflow_dispatch`。本仓库默认分支是 `v5`，所以仅在 `dev` 分支上加 `workflow_dispatch` 不会让 Actions 页面出现 Run workflow 按钮。必须把 CI 那个 commit 同步到 `v5`（cherry-pick + push），或把仓库默认分支改为 `dev`。

**待办**：默认分支问题解决后，在 Settings → Actions → General 确认 Actions 已启用。
